- **Captcha**: Cloudflare Turnstile (`@marsidev/react-turnstile`)

- **Deployment**: Vercel (connected to GitHub repo `SandeepSawhney2015/cadweb`, branch `main`)

```
MAIL_FROM_EMAIL                     # Sender address (optional). Defaults to developers@projcaden.dev.
MAIL_TO_EMAIL                       # Internal notification inbox (optional). Defaults to developers@projcaden.dev.
```

> **Switching to founders@parametra.ai:** set `MAIL_FROM_EMAIL=founders@parametra.ai` and
> `MAIL_TO_EMAIL=founders@parametra.ai` in Vercel — no code change needed. **Prerequisite:** the
> `parametra.ai` domain must be **Verified** in the Resend dashboard (SPF/DKIM DNS records) or all
> sends will fail. Until that's done, leave these unset so mail keeps flowing through the verified
> `projcaden.dev` domain. Both addresses are resolved in `lib/verification.ts` (`MAIL_FROM`,
> `INTERNAL_TO`, `SENDER_EMAIL`).

`NEXT_PUBLIC_` prefix exposes a var to the browser. All others are server-side only.

## Pages

### Home (`/`)
- Renders `DevBanner` + `IntroAnimation` + `Header` + `Hero` + footer
- `sessionStorage("introPlayed")` controls whether intro animation runs
  - First visit: animation plays, sets flag on completion
  - Return visit: skips animation, page appears instantly (`transition: none`)
  - "← Back to home" on success pages clears the flag so animation replays
- `mounted` state gates IntroAnimation to prevent hydration mismatch (sessionStorage not available on server)
- Footer: © year + nav links + `v1.5.0` centered in monospace dim text

### Intro Animation (`IntroAnimation.tsx`)
- Phases and timings:
  ```
  PHASE_RISE    = 80ms    logo + title rise from bottom
  PHASE_TEXT    = 350ms   tagline fades in
  PHASE_REVEAL  = 800ms   call onDone so page is ready underneath
  PHASE_SLIDE   = 900ms   overlay slides up (curtain reveal)
  PHASE_UNMOUNT = 1650ms  remove from DOM
  ```
- Locks `document.body.style.overflow = "hidden"` on mount, restores at PHASE_REVEAL
- `document.body.focus()` called at PHASE_REVEAL for scroll restoration
- Logo and title in a `flex-col items-center gap-0` container; title uses `mt-2 sm:-mt-6` — small positive gap on mobile, slight overlap on desktop (do NOT use large negative margins, it causes the logo to clip into the title on mobile)
- Color palette: blue (`rgba(37,99,235,...)`) and sky (`rgba(14,165,233,...)`)

## Database

### Schema (`waitlist_entries`)
```sql
id           SERIAL PRIMARY KEY
type         VARCHAR(20)   -- 'individual' | 'team'
name         TEXT
email        TEXT UNIQUE   -- normalized to lowercase, dedup key
role         TEXT
university   TEXT
reason       TEXT
organization TEXT
signed_up_at TIMESTAMPTZ
synced_at    TIMESTAMPTZ
deleted      BOOLEAN DEFAULT FALSE   -- soft-delete flag
deleted_at   TIMESTAMPTZ             -- when soft-deleted
```

### Email verification (`pending_verifications`)
```sql
email       TEXT          -- normalized lowercase
purpose     TEXT          -- 'waitlist' | 'contact'
code        TEXT          -- 6-digit code
payload     JSONB         -- the full form submission, held server-side
attempts    INT           -- wrong-guess counter (max 5)
expires_at  TIMESTAMPTZ   -- 10-minute TTL
created_at  TIMESTAMPTZ
PRIMARY KEY (email, purpose)
```
- Double opt-in: form submissions are stashed here on step 1; nothing is written to
  `waitlist_entries` / no message email is sent until the emailed code is confirmed on step 2.
- All logic lives in `lib/verification.ts` (`createVerification`, `verifyCode`, `sendVerificationEmail`).
- Server-side gate: `verifyCode` compares the code against this table — the client never receives it.
  Wrong codes burn an attempt; expiry, exhausted attempts, and success all delete the row.
- Code generated with `crypto.randomInt` (not `Math.random`). Run `npm run db:migrate` to create the table.

### Dedup logic
- Email normalized to `.toLowerCase()` on every write (form signup and sync)
- On signup: rebase DB first → check `deleted = FALSE` entries → 409 if found
- `deleted = TRUE` entries are returning users — allowed to re-register
- UNIQUE constraint on `email` is a second line of defense against race conditions (caught as `error.code === "23505"` → returns 409)

### Sync (`lib/sync-waitlist.ts`)
- Reads all rows from Google Sheet (Sheet1!A:H)
- Upserts each row into DB with `deleted = FALSE` (re-activates manually re-added users)
- Soft-deletes any DB rows (where `deleted = FALSE`) whose email is no longer in the sheet
- **Does not send any emails** — purely a DB operation
- Called in three places:
  1. `POST /api/waitlist` — before dedup check (to catch sheet deletions) and after signup
  2. `GET /api/sync-waitlist` — Vercel Cron, daily at midnight UTC
  3. `POST /api/sync-waitlist` — manual trigger via `x-sync-secret` header

### Running migrations
```bash
npm run db:migrate
```
Safe to re-run — uses `CREATE TABLE IF NOT EXISTS` and `ADD COLUMN IF NOT EXISTS`.

## Form Validation

Both `/signup` and `/contact` use the same validation pattern:

- `noValidate` on the form element — disables browser native validation
- `errors` state: `Record<string, string>`
- `validate()` — checks all required fields, returns boolean, sets all errors at once
- `clearError(field)` — removes a single field's error as soon as the user starts correcting it
- Tab switching clears all errors: `onClick={() => { setType(t); setErrors({}); }}`
- `inputClass(error?: string)` is a function — passes `"border-red-500/60"` when error present, `"border-white/10"` otherwise
- Inline error messages under each field: `errorClass = "text-xs text-red-400/80 mt-1.5"`
- Email validation: regex `/^[^\s@]+@[^\s@]+\.[^\s@]+$/` — shows "Please enter a valid email address."
- Captcha error shown if Turnstile not completed before submit

### Select Dropdown Styling
- `appearance-none` removes native browser arrow
- Custom SVG chevron via inline `backgroundImage` (URL-encoded), positioned `right 14px center`
- `pr-10` prevents text overlapping the chevron
- `font-sans` forces Geist Sans (select elements don't inherit font by default)
- Placeholder color: `rgba(255,255,255,0.25)` when no value selected, `rgba(255,255,255,1)` when value chosen — set via inline `style` since Tailwind can't conditionally override `text-white`

## API Routes

### `POST /api/waitlist`
**Two steps, selected by `body.step`:**
- **`step` absent → request** (`handleRequest`): captcha + validation + dedup, then `createVerification` stashes the submission and emails a 6-digit code. Returns `{ success: true, pending: true }`. Nothing written to the waitlist yet.
- **`step: "verify"` → confirm** (`handleVerify`): takes `{ email, code }`, calls `verifyCode`; only on a match does it run the full signup below. Errors map to HTTP status: `mismatch`/`not_found` → 400, `expired` → 410, `too_many_attempts` → 429.

Underlying operations (1–4 run on the **request** step; 5–9 run on the **verify** step after the code matches):
1. Verifies Cloudflare Turnstile token server-side
2. **Server-side field validation** — returns 400 if any required field is missing, email is invalid format, or `type` is not `"individual"` or `"team"`; also checks university required when role is Student
3. **Rebase DB** from Google Sheet (`syncWaitlist()`) — picks up any manual deletions before checking
4. **Dedup check** — queries DB for `email WHERE deleted = FALSE`; returns 409 `"already_registered"` if found
5. Detects returning users — `deleted = TRUE` entry means previously removed, sets `isReturning = true`
6. Sends two emails in parallel via Resend:
   - Internal: `developers@projcaden.dev` — full signup details
   - User confirmation: different subject/body for new vs returning users, includes spam notice
7. Appends row to Google Sheet + upserts to DB (parallel with emails)
   - Columns: Timestamp | Type | Name/Rep | Email | Role | University | Reason/Usage | Organization
8. **Rebase DB again** after signup to reflect new entry
9. Race condition: UNIQUE constraint violation (`error.code === "23505"`) caught → returns 409

### `POST /api/contact`
**Two steps, selected by `body.step`** (same pattern as waitlist):
- **request** (`handleRequest`): captcha + validation + **rate-limit check/increment** (moved here so verification emails can't be abused), then `createVerification` + emails the code. Returns `{ success: true, pending: true }`.
- **`step: "verify"`** (`handleVerify`): `{ email, code }` → `verifyCode` → only then sends the message email to the team + confirmation to the user.

Underlying operations on the request step:
1. Verifies Cloudflare Turnstile token server-side
2. **Server-side field validation** — same pattern as waitlist
3. Sends two emails via Resend in parallel:
   - Internal: `developers@projcaden.dev` — full contact details
   - User confirmation: echoes their message back as "pending reply", includes spam notice
4. Resend client initialized **inside** the handler — avoids build-time errors

### `GET|POST /api/sync-waitlist`
- **GET**: called by Vercel Cron (daily midnight UTC) with `Authorization: Bearer <CRON_SECRET>`
- **POST**: manual trigger with `x-sync-secret: <SYNC_SECRET>` header
- Both also accept `Authorization: Bearer <SYNC_SECRET>` as fallback
- Calls `syncWaitlist()` and returns `{ success: true, synced: N }`

### Shared validation helpers (in each route)
```ts
const EMAIL_RE = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
function missing(...vals: unknown[]) {
  return vals.some((v) => !v || (typeof v === "string" && !v.trim()));
}
```

## Known Quirks

- `SandeepHeashot.jpg` — filename typo (missing 'd'), keep as-is
- Logo is `/public/logo.svg` — referenced as `"/logo.svg"` via plain `<img>` tag in Header and Next.js `<Image>` in IntroAnimation
- `GOOGLE_PRIVATE_KEY` in `.env.local` has `\n` escaped as `\\n` — code does `.replace(/\\n/g, "\n")` to restore newlines at runtime
- Resend client in `contact/route.ts` initialized **inside** the handler; in `waitlist/route.ts` initialized at module level — both work, keep as-is
- `tabIndex={-1}` on `<body>` in `layout.tsx` — makes body programmatically focusable for scroll restoration after intro animation completes
- About page uses explicit `lg:items-start lg:text-left` / `lg:items-end lg:text-right` instead of dynamic Tailwind class names (v4 purges dynamic template literal classes)
- Turnstile widget requires network access to Cloudflare — may not appear on poor mobile connections
- Select `color` can't be conditionally overridden via Tailwind utility classes when `text-white` is already set by `inputClass` — use inline `style` instead
- `WAITLIST_STORAGE_POSTGRES_URL` is the env var name (not `POSTGRES_URL`) — Vercel prefixed it based on the database name when connecting
- `CRON_SECRET` is auto-generated by Vercel but must be manually added to env vars and set equal to `SYNC_SECRET` for the cron auth to work
